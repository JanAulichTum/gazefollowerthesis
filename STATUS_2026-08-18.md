## What changed (all pushed to `origin/main`)

1. **Head position is now captured automatically** (`b852f8c`) — was null
   in all nine manifests because it lived behind an opt-in button nobody
   clicked. Now fires at calibration and every validation phase.
2. **Full-affine correction candidate added**, gated at 12+ targets
   (`76aa944`) — the only candidate that can represent shear (`m_yx`,
   F33). Verified against a decision gate (does it actually help on the
   sessions that show shear, and only those) before writing any code.
3. **Grid A extended 7 → 13 targets** (`330b3c1`) — the sample size
   full-affine needs. Grid B (the out-of-sample check) unchanged at 7.
4. **F37**: the top ~12% of the screen undershoots in every one of the
   original 7 sessions with per-target data, 0.77°–5.62° (`2dd39fb`).
   Reported, no threshold encoded — see open items below.
5. **Two real bugs found via the first sessions recorded under (2)+(3)
   — PILOT_06 and PILOT_07 — and fixed** (`a285cd8`, `b8f934e`, `dade954`
   / F38):
   - `loo_errors` never handled `"full-affine"` — it returned `None`
     unconditionally regardless of sample size, so full-affine could
     **never** actually be selected, no matter how well it fit.
     PILOT_06's manifest shows the smoking gun: reported "unstable"
     with **0 of 13** leave-one-out folds actually failing.
   - `correction_audit.py`'s "needs re-derivation" flag only compared
     *none vs. something*, so "affine was applied, full-affine is now
     correct" read as no change.
   - Both fixed, mutation-tested, verified byte-identical on all nine
     pre-existing sessions (only the new sessions' output changed).
6. **Offset-correction claim tested end-to-end**, not just parameter
   recovery: does a systematically-offset held-out point actually land
   back near truth after correction, through the real production code
   path — first on one scenario, then across 20 varied ones (offset
   direction/magnitude, gain compression/expansion, noise levels, screen
   sizes) (`71d9908`, `3cd5a3d`). All promoted into `run_tests.py`.

**Test suite**: `run_tests.py`, 24 sections, every new check
mutation-tested (break it, confirm the test fails, restore). Green
throughout except 2 pre-existing, unrelated failures (macOS/pyobjc

**Head-position vs. shear (F33), first real data point** — with only 2
sessions this is not a conclusion, just what's observed: within a
session, shear swings substantially (`m_yx` range ~0.11 in both) while
head position (roll, face position, distance) barely moves — argues
against within-session head *drift* as the cause. Between the two
sessions, head placement differs and shear has opposite signs, which is
suggestive but statistically meaningless at n=2. Needs many more
sessions.

## What's genuinely fixed vs. what hasn't changed

**Fixed**: the code correctly does what it's supposed to do — corrections
are selected honestly, full-affine works when it should, held-out points
land back near truth, the audit tooling doesn't lie about what changed.

**Not fixed, because it isn't a code problem**: the instrument's real
ceiling. A systematic offset of ~1.1–2.6° that no correction removes
(F30), and shear that's real and measurable but not reliably fixable at
current sample sizes even with the best tool now available (PILOT_07).
That was never going to change from better code — it's what the
instrument measurably does.
